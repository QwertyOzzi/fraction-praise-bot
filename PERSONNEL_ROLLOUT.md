# FBI — карточки сотрудников и безопасность (черновая версия)

Эта ветка — **кандидат на обновление**, не автоматический деплой.
Не объединяйте PR с production до выполнения регрессионных проверок.

## Новые разделы Telegram

- /profile — личная карточка подтверждённого сотрудника: отдел, дата
  регистрации (если сохранена), ранг, FRP и похвалы, отчёты за 7/30 дней,
  история изменений ранга.
- /stats — руководству: рейтинг по одобренным отчётам за 7/30 дней.
  Это не онлайн и не показатель всей деятельности внутри игры.
- /department Nick_Name Название отдела — назначение отдела руководством.
- /permissions TelegramID permission allow|deny|clear — только владелец.
  Новые права хранятся в config/bot_state с отдельной подписью HMAC.
  Старые роли администратора/лидера не переинициализируются.

Агентские списания: по умолчанию /min разрешено только руководству,
а обычному сотруднику — после явного разрешения владельца points.debit.
Нужна причина после символа |, например:
/min frp Gomez_Addams -1 | Вручено по отчёту

Лимит одной операции: агент 1, заместитель 5, лидер/владелец 20.
Повторная проверка прав и баланса происходит при подтверждении.
Списание из панели /agents тоже запрашивает причину и записывается в
отдельный журнал agent_action_logs.

## Удаление

Удаление агента с нулевыми балансами использует единый Firestore commit
для двух таблиц и config/bot_state. При конфликте версий операция
отклоняется целиком. Подписанные роли остальных сотрудников сохраняются.
Удаление доступно только владельцу.

## Миграция в отдельные документы сотрудников

agent_directory_v2.py формирует возможное независимое содержимое каждого
сотрудника, сохраняя без изменений исходные строки обоих листов, включая
балансы и доказательства. При конфликте ников или идентичностей планирование
останавливается.

Офлайн-проверка бэкапа сайта:
    python tools/plan_agent_migration.py fraction_praise_backup.json --profiles bot_users_backup.json --output proposed_agents.json

--profiles — необязательный отдельный экспорт пользователей из состояния
бота. Не публикуйте его или предложенный JSON в открытых репозиториях.

ВАЖНО: сейчас работает старая схема sheets/fractionrp и sheets/praise.
Новый генератор — только dry-run без сетевых запросов и записи.
Полное переключение читателей/писателей нужно выполнять отдельно после
тестирования на копии Firestore и резервного копирования.

## Контроль перед деплоем

1. Проверить резервную копию sheets/*, config/bot_state, config/admins
   и config/settings; сохранить текущие Telegram роли.
2. Дождаться успешных CI проверок обоих PR.
3. В тестовой среде проверить владельца, лидера, зама и агента: проверку
   прав, списание, начисление, удаление, смену ника/ранга, перезапуск.
4. Сохранить активные Firestore Rules. GitHub не публикует правила Firebase.
   Не заменяйте активную политику устаревшей копией.
5. Внедрять после проверок; при проблеме откатывать код без сброса базы.

Поручения и мероприятия отсутствуют намеренно: согласовать логику с владельцем.
